# TCK-019 — NextAuth credentials wiring (authorize + JWT + role)

**Owner:** Backend
**Depends on:** none
**Priority:** P0

## Goal
Complete the NextAuth v5 Credentials flow: DB lookup, bcrypt verify, JWT session carrying user id + role.

## Acceptance criteria
- [ ] `authorize()` looks up user by email, verifies password with bcrypt, returns user or null
- [ ] Session strategy = JWT
- [ ] `jwt` callback puts `id` and `role` on the token; `session` callback exposes `session.user.id` + `session.user.role`
- [ ] Generic auth errors (no user enumeration)
- [ ] `POST /api/auth/register` creates a user (hashes password, validates email/password/phone, unique email → 409)
- [ ] TypeScript session/user types augmented for `id` + `role`
- [ ] `AUTH_SECRET` read from env; works over HTTPS
- [ ] End-to-end smoke: register → login → role present in session

## Technical notes
Pin the exact NextAuth v5 beta version (riskiest-assumption #3) and smoke-test early. bcrypt cost ≥ 10. `lib/auth-guards.ts` exports `requireUser()`/`requireAdmin()` used by pages and admin APIs. The `sessions` table stays unused under JWT.
