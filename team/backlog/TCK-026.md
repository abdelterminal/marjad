# TCK-026 — Admin order management + COD lifecycle

**Owner:** Both
**Depends on:** TCK-023, TCK-017
**Priority:** P0

## Goal
List and manage orders with a constrained COD status lifecycle.

## Acceptance criteria
- [ ] `GET /api/admin/orders` (filter by status + pagination), `GET /api/admin/orders/[id]` (order + items + product names)
- [ ] `PATCH /api/admin/orders/[id]` updates status, enforcing the valid transition table
- [ ] Order queue list: order #, customer, phone, city, total, status badge, date
- [ ] Order detail: items, quantities, unit prices, total, shipping info, customer contact
- [ ] Lifecycle actions surfaced: confirm, mark shipped, mark delivered, cancel (per allowed transitions)
- [ ] Illegal transitions rejected (e.g. delivered→pending → 422); `delivered`/`cancelled` terminal
- [ ] Shared `OrderStatusBadge` reused by account pages (TCK-021)

## Technical notes
Transition rules (architecture §5.1): pending→confirmed→shipped→delivered; cancel allowed from pending/confirmed/shipped. `processing` exists in the enum but is NOT a Phase 1 action (reserved). Enforce transitions in the PATCH validator server-side, not just UI.
